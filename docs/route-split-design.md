# 单路线拆分为多路线设计

## 背景

现有路线详情或岗位经常表示“这一组点位要被收完”，但它不一定是一辆车的一趟实际行驶路线。月山试点中也存在类似诉求：把一个已有岗位/路线的点位集合，拆成若干条可执行收运路线，并能继续套用多路线生成、终点择优、同车续跑和时间统计。

## 目标

第一版把“单路线拆分”做成和“多路线生成”平行的入口：用户选择一条已有路线或岗位，系统读取其规划点位，把这些点作为临时点位池，然后生成多条实际趟次路线。

拆分结果不直接覆盖原路线，而是作为预览结果导出或后续另存，避免破坏历史岗位配置。

## 输入

- 原始路线或岗位 ID。
- 原路线内规划点位，包含点位坐标、桶数、预计体积、预计重量。
- 起点配置：停车场、设施点或手填。
- 终点配置：固定终点、处置场任选、处置场及中转站任选。
- 车辆配置：不启用排班、按车辆顺序、车辆轮询、顺序后轮询兜底。
- 载重或未来的体积约束。
- 时间参数：每桶秒、每点分钟、行驶速度或 OD 道路耗时。

## 算法流程

1. 读取原路线点位，过滤掉无坐标点，形成拆分点位池。
2. 根据用户选择生成车辆排班计划。
3. 对每一趟执行当前多路线插入算法：从当前起点开始，在剩余点位中按距离增量插入，达到目标载重或无可选点时停止。
4. 若终点为任选，则对候选处置场/中转站逐个试算，选择该趟总距离最短的终点。
5. 同一辆车下一趟从上一趟实际终点继续出发。
6. 输出多趟路线、未分配点位、每趟行驶时间、点位作业时间、合计时间和路线明细。

## 页面建议

新增“路线拆分”页签，位置建议在“路线详情”和“区域划分”之间。

页面结构：

- 左侧：公司、路线/岗位列表、原路线点位池。
- 顶部参数：载重、最大趟数、规划策略、起终点、车辆排班、时间参数。
- 中部：原路线概览，展示原点位数、预计重量、预计体积、原始顺序。
- 右侧/下方：拆分结果，每一趟可查看地图、点位顺序、路段耗时、作业耗时。
- 操作：生成拆分路线、导出 Excel、未来另存为新路线/岗位。

## 和现有多路线生成的关系

单路线拆分不是新算法，而是现有多路线生成能力的一个新数据入口：

- 多路线生成：输入是公司点位池或区域分堆点位。
- 单路线拆分：输入是某条已有路线/岗位的点位。

后端可复用当前 `/api/optimize/multi-preview/tasks` 的核心逻辑，新增一个接口把 `routeId` 或岗位 ID 转成 `facilityIds`/点位池后调用同一套服务。

## 后续增强

- 支持把拆分结果保存为正式路线或岗位。
- 支持人工锁定部分点位必须在某一趟。
- 支持按 8 小时上限截停或提示超时。
- 支持体积约束优先于重量约束。
- 支持试跑反馈回写，修正速度和作业时间参数。
