# 少量时间窗联合规划

## 入口与范围

岗位页面“独立生成全点多趟方案”右侧新增按钮。允许时间段、禁止时间段均计入时间窗点，一个点只计一次。前端置灰，后端再次验证：仅1～5个时间窗点可执行。当前支持岗位所选的一辆车及其配置趟次，要求完整排班周期。

保留原有生成、时间窗修正、手动调整功能。不修改百度接口策略、点位坐标或进出口信息。道路仍为现有OD/百度策略得到的道路，不宣称地图最短路径。

处置场（设施类型5）不作为普通收运候选。原路线查询补充类型编号，岗位加载时排除处置场；后端多趟生成及联合插入再次过滤，旧数据只有类型名称时识别“处置场／处理厂”等明确类别，不根据点位名称猜测。时间窗点数量及每日应收点不包含处置场。配置的处理厂终点、卸料作业以及原始路线记录仍保留；无显式起终点配置的旧多趟请求保留原首尾锚点。更新前已生成的结果不会自动迁移，需要重新选择岗位并生成方案。

## 搜索

采用两阶段操作：先生成无时间窗点基础路线，状态为 `WAITING_INSERTION`，此时不枚举插入候选。弹窗按趟次展示基础道路和里程/耗时，紫色散点按真实坐标显示待插入点，不连接、不计入基础统计。没有无时间窗点时只展示待插入散点。

用户点击“开始尝试插入时间窗点（第二阶段）”后，复用第一阶段冻结的基础顺序、归属和参数，再准备完整矩阵并开始搜索，不重新生成基础路线。完成后地图展示候选路线，确认应用才替换当前模板。关闭第一阶段预览会取消等待中的任务；配置变化后必须重新生成。

1. 按当前参数生成无时间窗点的基础多趟路线。其相对顺序、归属、场站与趟序固定。
2. 配置但未使用的后续趟次可供时间窗点插入；不能突破配置趟数或车辆载重。
3. 将时间窗点依次插入所有允许趟次的所有位置，保留分支直到所有时间窗点均插入。枚举覆盖不同的时间窗点先后顺序，非每轮只保留一个候选。
4. 只用非负重量的容量条件剪枝；不因中间候选早到而剪枝，后续点可能延迟其到达。
5. 校验完整模板和每个排班日跳点后的道路、作业与时间窗，并检查同车累计工作时长。不自动等待。
6. 完整模板里程最短优先，里程相同时取耗时较少者。最优仅指该固定基础路线、配置趟次和现有道路矩阵下的插入候选，不是整体VRP全局最优。

基础规划存在未分配点、道路缺失或回退直线时直接失败，不输出假通过结果。无可行候选时保留原模板。未使用的配置趟次不计虚构卸料；已有非空模板趟次在每日跳点后保留其卸料，与现有每日执行语义一致。

## 计算与任务

任务内先准备所有候选需要的有向OD道路矩阵，每个点对最多准备一次；候选和每日校验仅访问此内存矩阵。路段速度依据候选路线当前点位密度、转场阈值重算，与普通道路分段口径一致。点位作业时间按本次参数和垃圾密度重新生成，不沿用旧模板的点位耗时。

后台单线程任务提供进度计数、插入组合上界和取消，不设候选数/运行时间上限。组合上界为插入槽数s下的s×(s+1)×…×(s+k-1)，实际容量剪枝后可能更少。点位≤5并不保证快速；总点数和配置趟数较多时应关注上界或取消。

弹窗顶部固定进度卡每秒更新：基础规划报告当前趟次；道路准备按去重后的有向点对报告完成数、真实百分比、缓存命中和百度补算数，并在请求前公布当前点对。查询尚未返回时不虚增计数，提示可能正在读取缓存或等待百度。搜索报告已检查完整候选数、可行数、超载剪枝分支数和当前最佳的合计里程/耗时；不把组合上界作为百分比分母。最佳候选仅供参考，全部搜索完成前不能应用。

同时显示本阶段运行时间和最近工作进度更新时间；第一阶段等待用户期间停止计时，第二阶段重新计时。15秒没有新工作进度时提醒可能在等待数据或校验，不直接判定卡死。取消或失败不返回部分最佳作为最终结果，原模板保持不变。

- POST `/api/optimize/small-window/tasks`
- POST `/api/optimize/small-window/tasks/{taskId}/insert`（仅允许等待插入阶段调用一次）
- GET `/api/optimize/small-window/tasks/{taskId}`
- POST `/api/optimize/small-window/tasks/{taskId}/cancel`

任务仅驻留后端内存，重启后丢失；保留少量终态任务供预览，新的任务可能清理旧终态记录。取消或失败不返回部分最优作为“已完成”。

## 应用与导出

先预览，不自动覆盖。点击“应用并替换全点模板”后重新构建每日跳点结果并复核时间窗、配置指纹；全部成功后才原子替换当前模板和每日结果。旧模板保留为恢复来源。现有全点导出和导出全部方案读取新的模板，无需另一个导出接口。

本功能修改前后端，需要更新前端资源并更新、重启后端。没有数据库结构迁移。上线验收仍需实际岗位数据验证按钮、取消、预览应用及Excel导出。
