# 岗位分配：选点自动调整

普通岗位方案、独立全点模板的“手动调整测试”新增“选点自动调整”模式。勾选按点位出现次序生成的唯一token，不按设施编号去重，因此保留同一设施多次出现的情况。每趟可选择若干收运点，选择可覆盖多个趟次；只能趟内挪动，起终点及内部卸料锚点固定，未勾选点保持相对顺序。

以点击开始时当前编辑列表为冻结基准，每轮尝试单点搬移、所选点交换、连续所选点的两点/三点/整段搬移及选中连续片段反转。整段动作独立于单点是否改善，能发现两个点一起搬移才改善的情况。全部候选比较后选取本轮最好可行改善，再进入下一轮；没有改善自然停止。按里程优先（差异不足1米时比较耗时），跳过重复顺序，不设固定轮数、候选数或运行时间上限。这是所选范围局部搜索，不枚举所有排列、不接受临时变差，不保证全局最优。

复用现有道路分段接口、手动对比和每日跳点重算。所有趟次按同车连续计时，验证完整模板及每个排班日的时间窗、应收覆盖、载重和累计工作时长。道路查询按完整点位顺序缓存；每种新顺序仍由后端按当前路线计算速度，不用固定点对耗时替代密度/转场速度估计。没有新的后端接口或数据库迁移。

当前最佳仅为进度信息，不自动写入编辑列表或主方案。完成后展示开始前基准与候选的地图、里程、耗时和超窗点；可显式采用到编辑列表继续调整，或复用保存替换与方案库另存。没有可行改善但存在更优超窗候选时单独显示黄色，不自动推荐；用户坚持替换时需二次确认。无改善则保留开始前顺序，不对不可行基准宣称可执行认证。

计算支持AbortController取消，结束或关闭清理计时器。取消/失败不返回或采用部分最佳，保留开始前编辑内容；用户配置或原方案变化仍由现有应用入口拒绝过期替换。进度显示轮数、候选累计数量、正在查询的趟次/日期、当前最佳和运行时间，不使用虚假百分比。

日期进度属于正在校验的单个候选，不是整个搜索只检查一次排班周期。进度明确区分基准复算和候选编号，展示“正在校验第N个候选／已完成M个候选”及本候选已完成的排班日数量、当前排班日序号和实际第几天。每个新候选从第1个排班日重新校验，43天后回到第1天时候选编号增加；候选完整校验结束后才增加已完成计数。

本次仅前端改动，刷新前端即可；后端不需重启。真实岗位数据、地图显示和替换后的导出需另行验收。
