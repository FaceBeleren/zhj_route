# 手动调整测试：只对比完整路线

当前岗位分配和全点模板的手动测试窗口均只计算完整路线，不生成或展示每日跳点场景。手动拖动仍按当前编辑顺序复算；选点自动调整改为一次贪心重插，不再调用多轮局部搜索。

选点一次重排：保留未选点的相对顺序，取出所选点，每步选择道路增程最小的点和插入位置，将所有选中点重新插入一遍。固定起终点、内部卸料锚点和趟次归属不变；不按时间窗筛选、不逐日搜索，不保证最优，也可能没有改善。前后完整路线均按同一道路数据和速度规则复算，点位收运及卸料时间保留，完整路线超窗仍标记；没有检查每日排班，不能把完整路线通过当作每日均通过。

后端新增 POST `/api/optimize/selected-points-once`：请求包含当前参数、routes和selectedTokens。所有点位出现token必须唯一，不允许选择锚点。任务内只预加载一次OD距离，插入比较从同一内存上下文取距离；必要点对缺失时按现有策略补算，失败禁止直线混算。只为调整前后路线加载最终道路几何，返回原序和新序的道路分段，前端复用返回结果，不再逐候选请求整趟道路。不启动新后台任务、循环轮次或候选计数；前端支持取消请求，取消后不采用部分结果。

用户可以预览、采用到编辑列表、另存或明确替换主方案；即使更差也可选择采用，超窗替换二次确认。这里只收窄测试窗口，主页面排班、应用后的现有每日刷新与导出行为保持原样。

本次涉及前后端，更新后必须重启后端并刷新页面；没有数据库结构迁移。真实岗位地图和导出需要另行验收。
